Getting started

The graph kernel: typed state, declared writes, budgets, traces, fan-out, async.

Preamble

Recipes for the part of GraphARC you touch first: a typed state model, nodes that declare what they write, edges that decide what runs next, and the machinery that stops a run before it costs you something. Every snippet was executed against this repo's .venv, and every block labelled Output is pasted from that run — not predicted, not tidied. Exactly one snippet is an exception: the real-model call near the end, labelled as unrun because it would spend money. tests/test_cookbook_basics.py reproduces every recipe and asserts these exact strings, so the page cannot rot quietly. Verified against grapharc 0.1.0, Python 3.14.6, langgraph 1.2.9, langchain-core 1.5.1, pydantic 2.13.4. Each snippet is a complete file; nothing carries over between recipes.

sharp edge Where output would depend on a clock or a random id, the snippet prints a stable projection instead and says which fields it dropped.

How do I install it?

Not on PyPI — git clone is the install path. Clone, cd, and uv sync --group dev. Check that it took with uv run grapharc --version, which prints grapharc 0.1.0. Everything below uses only the base install — no API key, no network, no optional extras.

How do I build and run my first graph?

Four moving parts: a state schema, a function, edges wiring it between START and END, and compile().invoke(). A node takes the state model (not a dict) and returns a dict of updates; it never assigns to state, and the returned dict is the only way anything leaves a node. On imports: GraphARC, GraphARCState, Budget, BudgetExceeded, BudgetMeter and WritePermissionError are on the top-level grapharc package; START and END are not — they come from grapharc.runtime.graph, along with StateTypeError, GraphCycleError, GraphRoutingError, MissingRunContextError, AsyncNodeError and RunContext.

python
from grapharc import GraphARC, GraphARCState
from grapharc.runtime.graph import END, START


class State(GraphARCState):
    question: str
    answer: str = class="tok-s">""


def answer(state: State) -> dict:
    return {class="tok-s">"answer": fclass="tok-s">"42 (you asked: {state.question})"}


g = GraphARC(State, name=class="tok-s">"hello")
g.add_node(class="tok-s">"answer", answer, writes={class="tok-s">"answer"})
g.add_edge(START, class="tok-s">"answer")
g.add_edge(class="tok-s">"answer", END)

print(g.compile().invoke({class="tok-s">"question": class="tok-s">"meaning of life"}))
sharp edge grapharc.runtime re-exports most names but not START, END or GraphCycleError, so from grapharc.runtime.graph import ... is the import that always works.

Why is a field missing from the result dict?

invoke() returns a plain dict of channel values, and a field that was never in the input and never written by a node is not one — its schema default is not materialised for you. Inside the graph your nodes always see a fully constructed State, defaults and all, because the model is rebuilt on the way into every node. The gap is only at the exit: LangGraph hands back the channel dict, not a model. State(**result) is the one-line fix, and it is worth doing at the boundary of your program anyway: it is also the moment your state model's own validators finally run.

python
result = g.compile().invoke({class="tok-s">"question": class="tok-s">"?"})
print(result)
print(State(**result))

How do I say what a node is allowed to write?

writes= is an allowlist, not documentation. A write outside it raises WritePermissionError and the update never reaches state. A node that writes nothing still needs the parameter: writes=set(); the check is on the keys of the returned dict, so returning None is the idiomatic "I wrote nothing" and is always legal. Note the asymmetry in when the two failures land: a typo naming a field the schema does not have is caught at add_node, because the schema is known then; a node writing a real field it did not declare can only be caught when it actually returns.

python
def write_draft(state: State) -> dict:
    return {class="tok-s">"draft": class="tok-s">"hello", class="tok-s">"published": class="tok-s">"hello"}   class="tok-c"># published is not declared


g = GraphARC(State, name=class="tok-s">"perms")
g.add_node(class="tok-s">"write_draft", write_draft, writes={class="tok-s">"draft"})
g.add_edge(START, class="tok-s">"write_draft")
g.add_edge(class="tok-s">"write_draft", END)

try:
    g.compile().invoke({})
except WritePermissionError as exc:
    print(exc)

try:
    GraphARC(State, name=class="tok-s">"perms").add_node(class="tok-s">"x", write_draft, writes={class="tok-s">"publised"})
except WritePermissionError as exc:
    print(exc)
sharp edge Neither failure is a warning; both stop the run.

How do I stop a node from mutating state behind my back?

You do not have to: every node gets a deep copy, so in-place mutation of a nested model is invisible to everyone else. Pydantic passes nested models by reference, so without the copy a node could rewrite state.report.title and have it stick — a write no writes= declaration approved and no trace recorded. The copy makes the returned dict the only channel out. The mutation is not an error, just local; if you want the change to land, return it.

python
def sneak(state: State) -> dict:
    state.report.title = class="tok-s">"rewritten in place"   class="tok-c"># not a declared write
    return {class="tok-s">"seen": state.report.title}


result = g.compile().invoke({class="tok-s">"report": Report(title=class="tok-s">"original")})
print(class="tok-s">"node saw: ", result[class="tok-s">"seen"])
print(class="tok-s">"state has:", result[class="tok-s">"report"].title)
sharp edge The cost is real — a model_copy(deep=True) per node execution, so a state carrying a 50 MB blob pays for that blob on every hop. Keep bulk data behind a path or an id in state, not in state.

How do I get a bad value rejected before it reaches the next node?

You already have it. Every value a node returns is validated against the declared type of its field at the node boundary, and the validated value is what gets written, raising StateTypeError otherwise. Constraints carried in the annotation (Annotated[int, Field(ge=0)]) bite too. The error names the node, the field, the declared type, the type that arrived and the value, because when this fires at 3am the question is always "which node did it". Writing "7" into an int field is accepted — Pydantic's default coercion — but what lands is the integer 7: a schema that says int means the result holds an int.

python
try:
    one_node(lambda s: {class="tok-s">"count": class="tok-s">"seven"}, writes={class="tok-s">"count"}).invoke({})
except StateTypeError as exc:
    print(exc)

out = one_node(lambda s: {class="tok-s">"count": class="tok-s">"7"}, writes={class="tok-s">"count"}).invoke({})
print(repr(out[class="tok-s">"count"]))
sharp edge This includes the last node before END, so a bad type cannot escape into the result.

Does my state model's own @field_validator run when a node writes?

No. This is the sharpest edge in the kernel. Write-time validation is built per field from that field's annotation, and the state model itself is never constructed — only the one field's value is — so a @field_validator declared on the state model has nothing to run against. Direct construction does run it; a write from the last node before END does not; add a node downstream and the model is rebuilt on the way in, so it does. The rule to hold in your head: writes= is GraphARC's; the types are Pydantic's, and only the annotation half of Pydantic. So prefer Annotated[...] constraints (Field(ge=0), Field(pattern=...), Field(min_length=1), Literal[...], StringConstraints(to_lower=True)) for anything you want enforced per write, or push the invariant into a nested model — the annotation is that model, so validating the write constructs it and its validators run.

python
class Article(BaseModel):
    slug: str

    @field_validator(class="tok-s">"slug")
    @classmethod
    def must_be_lower(cls, v: str) -> str:
        if v != v.lower():
            raise ValueError(class="tok-s">"slug must be lowercase")
        return v


class State(GraphARCState):
    article: Article | None = None


def publish(state: State) -> dict:
    return {class="tok-s">"article": {class="tok-s">"slug": class="tok-s">"NOT-LOWER"}}
sharp edge A violation written by the last node before END reaches your result unchecked; State(**result) at your program's boundary closes that.
sharp edge The gap is specifically the state model's own validators — anything one level down is fine.

How do I stop a graph that will not stop itself?

Give it a Budget. max_iterations is charged once per node execution and checked before every node, so a router that never says stop still stops. Crossing a budget raises BudgetExceeded; it does not return partial state — a truncated answer that looks like a real one is worse than an exception — which means the caller, not the graph, decides what to do about it. For a partial result, either catch BudgetExceeded and read the checkpoint, or build the stop condition into the graph so the run ends through END with a recorded reason. The budget is the ceiling, not the plan.

python
g = GraphARC(State, name=class="tok-s">"runaway", budget=Budget(max_iterations=5))
g.add_node(class="tok-s">"spin", spin, writes={class="tok-s">"spins"})
g.add_edge(START, class="tok-s">"spin")
g.add_conditional_edge(class="tok-s">"spin", again, {class="tok-s">"go": class="tok-s">"spin", class="tok-s">"stop": END})

compiled = g.compile()
try:
    compiled.invoke({})
except BudgetExceeded as exc:
    print(class="tok-s">"stopped:", exc.reason)

print(class="tok-s">"iterations charged:", compiled.last_run.meter.iterations)
sharp edge compiled.last_run holds the RunContext of the most recent invoke and is overwritten by the next invoke on the same compiled graph — read it before you run again.

How do I cap tokens and wall-clock time?

Same Budget; neither max_tokens nor max_seconds needs your nodes to cooperate. GraphARC installs a usage callback for the duration of every node, so any chat model invoked on that thread charges this run's meter, and the token ceiling is enforced at on_llm_end rather than waiting for the node to return — the LangChain "Error in MeterCallbackHandler.on_llm_end callback" line is that mechanism, not a second failure. max_seconds is delivered as an interrupt into the running node — SIGALRM on the main thread, PyThreadState_SetAsyncExc otherwise — which is why a node parked in time.sleep(5.0) dies at 0.25s. Budget also carries max_concurrency. Budgets are per-invoke, not per-thread: resuming a thread starts a fresh meter, and you can override with invoke(..., budget=Budget(...)).

python
try:
    one_node(talk, Budget(max_tokens=5)).invoke({})
except BudgetExceeded as exc:
    print(exc.reason)

t0 = time.monotonic()
try:
    one_node(nap, Budget(max_seconds=0.25)).invoke({})
except BudgetExceeded as exc:
    print(exc.reason.split(class="tok-s">" (")[0])
print(f"gave up after under a second: {time.monotonic() - t0 < 1.0}")
sharp edge A node inside a C call cannot be unwound by the second mechanism; the signal path needs invoke() on the process's main thread, so driving a run from a ThreadPoolExecutor or threaded request handler silently falls back to the weaker mechanism.
sharp edge A node that catches every interrupt and never returns cannot be stopped from Python at all (the interrupt is re-armed every 50 ms, but while True: around except BaseException still hangs you).
sharp edge Even when the node survives the interrupt, the deadline holds at the node boundary — an overrun node's writes never reach state.

How do I forbid cycles until I actually need one?

dag=True. Cycles are something you earn, not something you start with. Static edges can only be judged together, so a cycle built from them waits for compile() and GraphCycleError names the cycle it found (a -> b -> a) rather than saying "graph is cyclic". Conditional and fan-out edges are refused at add_* time, because in dag mode there is no version of them that would be legal later.

python
g = GraphARC(State, name=class="tok-s">"pipeline", dag=True)
g.add_node(class="tok-s">"a", bump, writes={class="tok-s">"n"})
g.add_node(class="tok-s">"b", bump, writes={class="tok-s">"n"})
g.add_edge(START, class="tok-s">"a")
g.add_edge(class="tok-s">"a", class="tok-s">"b")
g.add_edge(class="tok-s">"b", class="tok-s">"a")        class="tok-c"># accepted here...
g.add_edge(class="tok-s">"b", END)

try:
    g.compile()             class="tok-c"># ...and refused here
except GraphCycleError as exc:
    print(exc)
sharp edge GraphCycleError is the one exception grapharc.runtime does not re-export — import it from grapharc.runtime.graph.

How do I write a loop that ends for a reason instead of running out of road?

Route with code, and record why you stopped in state. ProgressGuard gives you three independent brakes — a target, a no-progress window, and a round cap — and assess() returns the first one that trips as a StopReason. In the example the target of 10 findings was never met, but the loop stopped anyway at round 4 with no_progress on the record, and the 50-iteration budget was never touched: the budget is the thing that catches your bug, not the thing that ends your run. Routers are ordinary Python functions over typed state — no model output is ever consulted to pick an edge, so a model writing ROUTE TO: all_verified into a state field is writing a string, not choosing a branch.

python
GUARD = ProgressGuard(target=10, max_rounds=8, max_empty_rounds=2)


def decide(state: State) -> dict:
    stop = GUARD.assess(
        round=state.round,
        total_findings=state.findings,
        empty_rounds=state.empty_rounds,
    )
    return {class="tok-s">"termination_reason": stop.value if stop else None}


def route(state: State) -> str:
    return class="tok-s">"stop" if state.termination_reason else class="tok-s">"again"


g.add_conditional_edge(class="tok-s">"decide", route, {class="tok-s">"again": class="tok-s">"search", class="tok-s">"stop": END})
sharp edge add_conditional_edge passes router and mapping straight through to LangGraph; GraphARC does not check that the router's return values are keys of the mapping — a typo is a run-time KeyError. StopReason is a StrEnum, so using its members as mapping keys makes that typo impossible.

How do I see what actually happened?

Hand the graph a TraceRecorder. Every node execution writes a start line and then either an end or an error line, as JSONL. start carries identity only (run, thread, attempt, graph, node, step, timestamp) and is written before the node body, so it exists even when the node never returns; end adds state_delta (exactly the validated update applied), duration_ms and tokens; error adds duration_ms and error (repr() of the exception, so the type is preserved) and has no state_delta, because a node that raised wrote nothing. start and end share a step number — the pair is the node execution — so step numbers do not order the file; read events in file order (the recorder appends under a lock). The grapharc trace, grapharc metrics and grapharc viz commands read this exact file, which is why the dashboard and the audit trail cannot disagree.

python
trace = TraceRecorder(tmp / class="tok-s">"trace.jsonl")

g = GraphARC(State, name=class="tok-s">"counter", trace=trace)
...
VOLATILE = {class="tok-s">"ts", class="tok-s">"run_id", class="tok-s">"thread_id", class="tok-s">"duration_ms"}
for event in trace.read_events():
    print({k: v for k, v in event.model_dump(exclude_none=True).items() if k not in VOLATILE})
sharp edge Nodes may emit their own phases on the same recorder — treat the phase set as open rather than exhaustive.
sharp edge Long values are truncated at 2000 characters with a …[truncated N chars] marker and non-JSON-able values fall back to repr(); a trace is an audit trail, not a serialisation format.

How do I see what a run spent, from inside a node?

Give your node a second parameter. Any node function with two or more parameters receives the RunContext as the second one, and the rule is detected from the function signature, so you never register which form you wrote. ctx.meter.tokens is populated without the node charging anything by hand — the usage callback did it. RunContext also carries run_id, thread_id, attempt and graph, which is what you want when a node writes to something outside the graph and needs to stamp it with the run that produced it.

python
def talk(state: State, ctx: RunContext) -> dict:      class="tok-c"># two parameters => you get ctx
    model = ScriptedChatModel(responses=[class="tok-s">"a scripted reply"])
    reply = str(model.invoke([HumanMessage(content=class="tok-s">"hi")]).content)
    return {class="tok-s">"reply": reply, class="tok-s">"spent_so_far": ctx.meter.tokens}
sharp edge Adding a defaulted second parameter for your own reasons — def node(state, retries=3) — silently turns it into a ctx parameter, and retries will be a RunContext. Keep extra arguments in a closure or in state.
sharp edge A bare ctx.meter.charge_tokens(n) is always counted even when the callback already metered that call, so hand-metering an automatic call pays twice; pass the message: charge_tokens(n, source=message).

How do I resume a run that died halfway?

Compile with a checkpointer, then call invoke(None, thread_id=...) to resume that thread from its last checkpoint — input=None means "resume". get_state("t1").next tells you what will run, and in the example exactly one fetch happened across both attempts. Crash-safe resume is LangGraph's, not GraphARC's: the checkpointer passed to compile() goes straight through. What GraphARC adds is trace continuity — after a resume, step numbers continue from the thread's history and attempt increments, so (thread_id, step) stays unique across attempts and one logical thread is stitchable across restarts.

python
compiled = (
    GraphARC(State, name=class="tok-s">"fetch_save")
    .add_node(class="tok-s">"fetch", fetch, writes={class="tok-s">"data"})
    .add_node(class="tok-s">"save", save, writes={class="tok-s">"saved"})
    .add_edge(START, class="tok-s">"fetch")
    .add_edge(class="tok-s">"fetch", class="tok-s">"save")
    .add_edge(class="tok-s">"save", END)
    .compile(checkpointer=SqliteSaver(conn))
)

print(class="tok-s">"next to run:", compiled.get_state(class="tok-s">"t1").next)
result = compiled.invoke(None, thread_id=class="tok-s">"t1")     class="tok-c"># input=None means class="tok-s">"resume"
sharp edge SqliteSaver needs check_same_thread=False because LangGraph runs nodes on worker threads.

Does that survive a real process kill?

Partly. LangGraph's default checkpoint durability is "async" — the checkpoint for a completed step is written in the background while the next step starts — and CompiledGraphARC.invoke() does not expose the durability parameter to change it. After a SIGKILL the run resumed and produced exactly one result, but fetch ran twice: no checkpoint reached disk saying "fetch is done, start at save", so the resume replayed from the beginning. What to do: make nodes idempotent, or make the expensive step's effect externally deduplicated (content-addressed path, upsert on a key, check before you fetch) — the right answer regardless of durability mode, since a node can also be re-run by a retry or a deliberate resume from an earlier checkpoint.

python
    def save(state: State) -> dict:
        if os.environ.get(class="tok-s">"KILL_ME"):
            os.kill(os.getpid(), signal.SIGKILL)
        return {class="tok-s">"saved": True}
sharp edge Do not treat "it was checkpointed" as "it will not run again".
sharp edge durability="sync" exists on LangGraph's Pregel.invoke and would keep the post-fetch checkpoint, but reaching it means bypassing CompiledGraphARC.invoke() — and .inner.invoke() fails closed, so there is no supported path to it right now.
sharp edge How much got written before the kill is itself a race — the step-0 checkpoint sometimes lands and sometimes does not.

Why can't I just call .inner.invoke()?

Because a run with no budget and no trace is not a GraphARC run, and failing silently into one is the bug this prevents — raw LangGraph entry points raise MissingRunContextError. .inner is an inspection escape hatch, not an execution one: compiled.inner.get_graph().draw_mermaid() works fine, as does anything else that reads; only the entry points that would run nodes fail closed. GraphARC already wraps get_state, get_state_history and update_state on the compiled object, so you rarely need .inner at all — and the wrapped update_state type-checks your values and, when you pass as_node=, applies that node's write allowlist.

python
try:
    compiled.inner.invoke({})       class="tok-c"># raw LangGraph entry point
except MissingRunContextError as exc:
    print(exc)

How do I fan out across workers without one of them sinking the run?

add_fanout_edge dispatches parallel Sends; run_guarded turns a worker's crash or hang into data. Use both — the first alone gives you parallelism with a shared fate. The pieces: input_schema=Shard types the payload a worker receives (a fan-out worker is called with the Send payload, not the graph state, which is why worker never reads state); a reducer on the target field, Annotated[list[WorkerResult], operator.add], is what lets three parallel workers all write results without clobbering each other; run_guarded runs the job on a daemon thread joined with a timeout, so a raised exception becomes WorkerResult(ok=False, error=repr(exc)) and a hang becomes ok=False, error="timeout after 0.2s"; Budget(max_concurrency=2) caps how many workers run at once. Two of three workers died — one crashing, one hanging — and the run still produced an answer with both failures attributed by cause.

python
def worker(shard: Shard) -> dict:
    def job() -> list[dict]:
        if shard.fail:
            raise RuntimeError(class="tok-s">"shard parser blew up")
        if shard.hang:
            time.sleep(shard.hang)
        return [{class="tok-s">"word": w} for w in shard.words]

    return {class="tok-s">"results": [run_guarded(job, worker=shard.name, timeout_seconds=0.2)]}


g = GraphARC(State, name=class="tok-s">"fanout", budget=Budget(max_concurrency=2))
g.add_node(class="tok-s">"worker", worker, writes={class="tok-s">"results"}, input_schema=Shard)
g.add_fanout_edge(class="tok-s">"prepare", dispatch)
sharp edge A hung worker is abandoned, not killed — the daemon thread keeps sleeping, a late result is ignored, and a worker holding a lock or file handle keeps holding it.
sharp edge The fan-out timeout is per worker and separate from Budget(max_seconds=...), which is per run.
sharp edge Drop the Annotated[...] reducer and LangGraph raises InvalidUpdateError: At key 'results': Can receive only one value per step. — it does not silently pick a winner.
sharp edge Without run_guarded, one bad worker takes the whole run with it.
sharp edge A dispatcher naming a node the graph does not have raises GraphRoutingError; plain LangGraph logs Ignoring unknown node name and carries on, so the shard is never worked and your answer is quietly built from two thirds of the evidence. END is not a valid Send target.

Can my nodes be async?

Yes — and if a graph has any async def node you must use ainvoke/astream, which it will tell you via AsyncNodeError. The rejection happens before any node runs, so a graph mixing sync and async nodes cannot half-execute; plain LangGraph would run every sync node first and then fail on the first coroutine. Sync nodes stay legal under ainvoke() — LangGraph runs each on a worker thread.

python
print(asyncio.run(compiled.ainvoke({})))

try:
    compiled.invoke({})
except AsyncNodeError as exc:
    print(exc)
sharp edge For an async def node, max_seconds is delivered as task cancellation rather than a thread interrupt, so it lands at an await — an async node doing blocking work between awaits is not interrupted until it yields.
sharp edge If you read README.md first and saw "No async" under Status, trust the snippet above — it ran.

How do I swap the scripted model for a real one?

Everything above used grapharc.testing.ScriptedChatModel, a real BaseChatModel that replays a fixed list of strings and reports plausible usage metadata — so budgets, traces and the usage callback are all exercised for free. Swapping in a real backend is a one-line change at the point of construction via grapharc.gateway.get_model. What you can check without spending anything is how a spec resolves, with describe, which never constructs a model and never touches a credential; a mistyped backend is rejected rather than folded into a model name, so opnerouter/... fails there instead of failing much later as a nonsense Claude CLI call. Once a real model is in a node, nothing else on the page changes: the usage callback charges the run's meter whether the model is scripted or real, including calls made deep inside library code your node merely called — the whole reason max_tokens is worth setting.

python
from grapharc.gateway import get_model

class="tok-c"># Claude Code CLI: uses your Claude subscription, no API key. Text completion only —
class="tok-c"># bind_tools and with_structured_output raise NotImplementedError on this backend.
model = get_model(class="tok-s">"claude-cli/claude-sonnet-5")

class="tok-c"># OpenRouter: needs OPENROUTER_API_KEY and the `openrouter` extra
class="tok-c"># (uv sync --extra openrouter). Tool calling, structured output, streaming, async.
model = get_model(class="tok-s">"openrouter/anthropic/claude-haiku-4.5")

class="tok-c"># OpenAI directly: needs OPENAI_API_KEY and the `openai` extra.
model = get_model(class="tok-s">"openai/gpt-4o-mini")

class="tok-c"># Ollama: a model on this machine. No key, no bill — the one real backend you
class="tok-c"># can run without an account. Needs the `ollama` extra and a pulled model.
model = get_model(class="tok-s">"ollama/llama3.1")
sharp edge The get_model snippet was NOT executed — it calls a paid or subscription-metered backend, and this cookbook does not run those. It is here for the shape only.
sharp edge On the claude-cli backend, bind_tools and with_structured_output raise NotImplementedError.

What this page did not cover

Deliberate omissions, so you know they exist rather than discovering them: stream() / astream() / astream_events() — the same discipline, incremental output, and .inner.stream() fails closed exactly like .inner.invoke(); returning a langgraph Command from a node for dynamic goto routing, whose update goes through the same allowlist and type checks and whose destination is checked against the graph's nodes; update_state for human-in-the-loop edits between steps; and the model gateway's retry policies, spend meters and cost ceilings, verification (verify_claim), memory, and the tool harness — other pages.

sharp edge A state model's own @field_validator / @model_validator does not run when a node writes — only the field's annotation is enforced (which does include a nested model's own validators). Rebuild the model at your program's boundary, or keep the invariant one level down.
sharp edge add_conditional_edge does not verify that your router's return values are keys of your mapping. A typo is a run-time KeyError.
